# План: бот на онлайн-лекции SSAU

Личный инструмент на ~5 человек одной группы. Не публичный SaaS.

## Зачем

Не сидеть на онлайн-парах, но:

1. **Посещаемость** — в BBB в списке участников видно ФИО, как в журнале. Камеру не просят, микрофон не нужен.
2. **Пейджер** — на паре лёгкий споттинг вейквордов по **одному** аудиопотоку: фамилия, «тест», «контрольная», «мудл». Это не расшифровка лекции. Полный текст — **после** пары, по API.
3. **Архив** — часть пар не пишется универом. Раз уже внутри комнаты, один раз пишем звук на диск VDS.

За 15 минут до пары в личку: предмет, препод, время, кнопки Да / Нет. Молчание = зайти. Нет = сегодня пропуск.

## Что сознательно не делаем

- Логин в личный кабинет и Moodle — слишком дорого и хрупко.
- Резидентские прокси и антибот-обход. Обычный SOCKS5 с RU IP, по одному на человека, настраивает админ.
- Автопрохождение тестов, ответы в чат BBB, включение камеры/микрофона.
- Отдельная копия записи на каждого кента, если это одна и та же лекция.
- Полный Whisper/большая модель **во время** пары. На лекции только Chrome + запись + крошечный keyword-споттер.

## Решения с гриля

| Тема | Решение |
| --- | --- |
| Кто | Я + кенты, одна группа, потолок ~5 человек |
| Площадка | `bbb.ssau.ru` (Greenlight), заход **гостем**, поле имени как скажет человек боту |
| Расписание | Публичный `https://ssau.ru/rasp?groupId=…`. Слово `online` в поле места — это онлайн, **не ссылка** |
| Ссылка BBB | В расписании её нет. При **первом** заходе на такую пару бот спрашивает URL `bbb.ssau.ru/b/…` и запоминает |
| Подгруппа | В профиле есть. Сейчас все в **1**, чужие подгрупповые онлайны не берём |
| Telegram | Один бот. Отвечает **только** айдишникам из вайтлиста. Чужим — тишина |
| Админ-панель | Mini App только у `1074442235`: вкладки + пульт + логи. HTTPS без своего домена (туннель) |
| Парсер-ключи | Позже: ключи от кентов (Fish Studio и ещё что дадут). Слот в конфиге есть, в v1 не блокер |
| Прокси | SOCKS5, разные IP кентам. Раскидывает админ на VDS, не каждый в боте |
| Аудио в BBB | Всегда «только слушать». Лобби >2 мин → алерт «не пустили» |
| Выход | Случайные 0–5 минут **до** конца слота из расписания (преподы сами часто режут раньше) |
| Запись | Папка на VDS. Одна лекция = один файл, даже если зашло пятеро |
| Вейкворды | Живые, по одному потоку. Короткие слова, не полный транскрипт. Расшифровка лекции — API после записи |
| Железо | VDS **4 CPU / 4 ГБ RAM + 4 ГБ swap**. Один Chrome: 1 умная вкладка + 4 в списке |
| Рефреш расписания | Фон: **07:00, 15:00, 19:00, 22:00** (локальное время Самары). Изменилось — перезаписать |

Группа-якорь: `6301-090301D`, `groupId=531023229`.

## Вайтлист Telegram

Бот не онбордит с улицы. Нет id в списке — нет ответа (и нет Mini App).

| Роль | Telegram user id |
| --- | --- |
| Админ (я), Mini App | `1074442235` |
| Кент | `2047776316` |
| Кент | `808176356` |
| Кент | `1523691310` |
| Кент | `1098241114` |

Итого 5 человек, как в потолке. Сиды в конфиге, живое состояние (вкл/выкл, прокси, ФИО, вейкворды) — sqlite, крутится из Mini App.

## Админский Telegram Mini App

Пульт, не картинка. Открывается **только** у `1074442235`. Кентам — обычные лички, без `web_app`.

Глобальную Menu Button в BotFather не ставим (она у всех). `/panel` и `web_app`-кнопка **только в чате админа**. На старте бота `setChatMenuButton` для этого chat id, URL из `WEBAPP_PUBLIC_URL`. Сервер: HMAC `initData` → user id == админ, иначе 403.

Стек UI: статика из того же Go-бинарника (без отдельного Node-сервера). Пока вкладка «Сейчас» открыта — пуллинг **5–10 сек**. WebSocket не тащим. Смена состояния (зашёл / лобби / вылетел / парсер упал) дублируется пушем в ТГ админу.

### Вкладки

**Сейчас**

- какие TG-аккаунты из вайтлиста «в боте» (профиль есть, не выключен)
- кто реально сидит в BBB: в комнате / лобби / нет
- на какой паре бот сейчас (предмет, препод, слот, ссылка)
- какая пара следующая
- короткий статус записи (пишется / нет)

**Люди**

- карточка каждого: telegram id, username, имя/фамилия из ТГ, ФИО для BBB, подгруппа, вкл/выкл
- какой SOCKS5 на ком (править с панели)
- оригинальные вейкворды: общие + персональная фамилия и что человек дописал
- управление кентом: выключить навсегда / на сегодня, сменить ФИО и подгруппу

**Пары**

- сетка: online vs очно, подгруппа
- сохранённые ссылки BBB (ключ дисциплина+препод → URL), можно вставить/поменять
- какие лекции уже лежат в `recordings/` (имя файла, слот, размер)

**Парсер**

- последний прогон: время, ок/403/пусто, сколько пар, сколько online
- дифф, если сетка изменилась
- кнопка **обновить расписание прямо сейчас** (не ждать 7/15/19/22)

**Логи**

- лента событий с VDS: join, leave, лобби, ошибка прокси, репарс, вейкворд, «нет ссылки BBB»
- кто, какая пара, сырой текст ошибки
- хвост в sqlite (последние N), не Grafana

### HTTPS без своего домена

Telegram Mini App **не умеет** голый `http://ip:port`. Свой домен и Caddy **пока не поднимаем** — впадлу.

v1: рядом с бинарником туннель с валидным HTTPS, без DNS:

- бесплатный статический хост ngrok (`*.ngrok-free.app`) — URL не прыгает после рестарта
- или `cloudflared tunnel --url` (`*.trycloudflare.com`) — URL каждый запуск новый, тогда прописать в `.env` и перезапустить бота (он сам обновит кнопку админу)

`WEBAPP_PUBLIC_URL` в `.env`. Когда надоест ротация — купим домен, туннель останется тем же кодом.

## Ключи парсеров / STT со стороны

Кенты могут притащить API-ключи (назвали **Fish Studio**, плюс «ещё посмотрим»). Это **полная расшифровка после пары**, не стрим на лекции. Ключ в `.env`. Пока ключей нет — ogg копим, текст лекции не строим. Вейкворды от этого не зависят.

## Как это живёт

```
Telegram ──► bot (Go) ──► sqlite
     │              │
     │              ├─ cron расписания (4 раза в день)
     │              ├─ таймеры пар (T-15, join, leave)
     │              ├─ HTTPS + Mini App (только админ, initData)
     │              └─ worker BBB
     │                    ├─ 1 Chromium, 5 вкладок (свой SOCKS5 / ФИО на вкладку)
     │                    │     1 «умная» со звуком, 4 тупо в списке
     │                    └─ 1 захват звука + лёгкий keyword-споттер (не Whisper)
     │
     └─ кенты: только bot API (сообщения)
         админ: bot API + WebApp
```

Один процесс, один бинарник. Chromium ставится на VDS рядом, не бандлится в бинарник.

## Стек

**Go**, не Python и не «ещё один скрипт». Нужен маленький статичный бинарник на VDS: systemd, `scp`, всё.

Почему не Rust: автоматизация BBB — это браузер (WebRTC, гостевая форма, «только слушать»). В Go это `rod`/`chromedp` за дни, в Rust — боль. Парсер HTML, Telegram, cron, SOCKS5 — для Go родное.

Намётки пакетов (не догма):

- Telegram: `gotgbot` или `telego`
- Расписание: `net/http` + `goquery`
- Браузер: `go-rod/rod` (удобнее живого BBB, чем сырой chromedp)
- Хранение: SQLite (`modernc.org/sqlite` или `crawshaw`) — пользователи, ссылки BBB, снимок расписания
- Звук: ffmpeg с одной вкладки. Параллельно крошечный keyword spotting (Vosk grammar / аналог) по тому же потоку: десятки–пара сотен МБ, не гигабайт.
- Полная расшифровка: **после** файла, внешнее API. Большой Whisper на VDS во время пары не ставим.

Конфиг: `.env` + файл прокси. В git не попадает.

## Секреты и ключи

В git не класть. Живут в `.env` на машине разработки и на VDS.

**Чтобы бот и Mini App вообще завелись — одно:**

| Что | Зачем | Откуда |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Писать/читать сообщения, кнопки Да/Нет, валидировать `initData` вебаппа (HMAC). Отдельного «ключа Mini App» нет | [@BotFather](https://t.me/BotFather) → `/newbot` → токен вида `123456:AAH...` |

Это **Bot API**, не userbot. `api_id` / `api_hash` с my.telegram.org **не нужны**. Айдишники кентов — не секреты, они уже в вайтлисте.

В BotFather ещё руками (не ключи): выключить группу/инлайн если не надо; URL Mini App можно не прописывать глобально — бот сам ставит кнопку админу через `setChatMenuButton`.

**Потом, не блокер старта:**

| Что | Когда |
| --- | --- |
| `WEBAPP_PUBLIC_URL` | Не секрет. HTTPS-адрес туннеля, чтобы открылась панель |
| `NGROK_AUTHTOKEN` | Если берём ngrok, а не cloudflared quick tunnel. Бесплатный аккаунт ngrok |
| SOCKS5 `user:pass@host:port` на каждого кента | Когда начнём реальный заход в BBB с разных IP |
| Fish Studio / прочие ключи от кентов | Расшифровка **после** записи. На паре не вызываем |
| Логин/пароль SSAU, Moodle, ЛК | **Не берём**, так и задумано |

Локально и на VDS один и тот же `.env`. Для разработки достаточно токена бота: парсер rasp ходит на публичную страницу без ключей.

## Данные

**Пользователь:** telegram id, строка ФИО для BBB, groupId, подгруппа, включён ли, какой SOCKS5 ему назначен (ссылка на запись админа).

**Группа:** url/id расписания, последний сырой снимок, последний распарсенный список пар.

**Пара:** день, слот (08:00–09:35 и т.д.), дисциплина, препод, место (`online` / аудитория), подгруппа, тип.

**Ссылка BBB:** ключ ≈ `groupId + дисциплина + препод` (комната Greenlight обычно живёт семестр). Значение — URL. Если ключ пустой в момент T-15 — спросить ссылку в личке, без неё не заходить.

**Запись:** `recordings/{date}_{time}_{discipline}.ogg` плюс мета (кто из пользователей «присутствовал»).

**Событие (логи панели):** время, тип, telegram id, id пары, сообщение. Хвост для вкладки «Логи».

## Онбординг в Telegram

1. Пишет человек. Id нет в вайтлисте → **молчание**.
2. Id в списке, профиля ещё нет → бот коротко говорит, зачем он.
3. Ссылка расписания: пока общая `groupId=531023229` (админ может сменить из панели).
4. «Как тебя записать в BBB?» — строка как в журнале. Фамилия для вейкворда = первое слово.
5. Подгруппа, дефолт `1`.
6. Дальше лички только этому id: T-15, вейкворды, «кинь ссылку BBB».

Админ после `/start` ещё получает кнопку Mini App (`/panel`). Прокси и прочая грязь — из панели, не через онбординг кентов.

## Парсер `ssau.ru/rasp`

Публичная страница. Онлайн = `.schedule__place` содержит `online`. Препод — ссылка `/rasp?staffId=`. Подгруппа — текст `Подгруппы: N`. Слоты из колонки времени.

Рефреш в 7 / 15 / 19 / 22. Если сетка изменилась — перезаписать пары, пересчитать таймеры. Очные пары игнор, кроме того что они не должны порождать join.

Сайт иногда отдаёт 403 без нормального UA/cookie — парсеру нужен браузерный UA и, если понадобится, cookie с первой загрузки `/rasp` (как у чужих ssau-парсеров).

## Заход в BBB

На каждую включённую онлайн-пару и каждого кента с подходящей подгруппой:

1. T-15: карточка в ТГ (предмет, препод, время, Да/Нет).
2. Если ссылки комнаты нет — в той же карточке/следом: «кинь ссылку на подключение». Запомнить. Если так и не кинули — не заходим, написать об этом.
3. Молчание / Да → один процесс Chromium `--headless=new`. Пять вкладок, у каждой свой локальный SOCKS-форвардер и своё ФИО.
4. Одна вкладка — listen-only, с неё запись и споттер. Остальные четыре только чтобы имя висело в списке, медиа не поднимаем (если BBB выкинет без аудио — тогда listen-only всем, писать всё равно одну).
5. Если зависли в waiting room — алерт.
6. Выйти в случайный момент из интервала `[конец_слота - 5 мин, конец_слота]`.

Пять человек = пять вкладок в **одном** Chrome, не пять процессов.

## Вейкворды

Это не расшифровка. Споттер слушает короткий список и орёт в ТГ сразу:

- всем на этой паре: `тест`, `контрольная`, `мудл` (`moodle`)
- лично: фамилия из ФИО, как записали в BBB

Один поток на комнату, не пять моделей. На 4 ГБ это мелочь рядом с Chrome. Полный текст лекции споттер не строит.

После выхода: ogg → API (Fish и т.п.) → конспект/поиск. Квизы в Moodle руками.

## VDS

- Linux, Chromium, ffmpeg, бинарник под systemd. Без Docker и без nginx: бинарник сам отдаёт Mini App, TLS даёт туннель.
- Выкат: пуш в `plan` → GitHub Actions собирает linux/amd64 и по SSH кладёт `/opt/ssau-bot` + `ssau-bot.service`. `.env` на сервере руками, в деплой не входит.
- **1 CPU / 1 ГБ хватит** на бота + парсер + sqlite + панель (этапы 1–4).
- На заход: **4 CPU / 4 ГБ RAM + 4 ГБ swap**. Один процесс Chrome, пять вкладок: одна слушает и пишет, четыре только ФИО в списке. Whisper на паре нет.
- 8 ГБ RAM — только если на живой паре всё равно OOM, не как старт.
- Диск под `recordings/`. Ротация не в v1, следить руками.
- Исходящие: Telegram API, `ssau.ru`, `bbb.ssau.ru`, SOCKS5.
- Входящий HTTPS для Mini App через туннель (ngrok / cloudflared), **без своего домена** в v1. Telegram всё равно требует валидный TLS — туннель его даёт.

## Риски (не прикидываемся, что их нет)

Посещаемость гостем с чужим/своим ФИО и запись пары — серая зона правил универа и BBB. Инструмент заточен под конкретную группу, репозиторий **приватный**. Не светить токены, прокси и записи.

Технически хрупко: смена вёрстки rasp, новая ссылка комнаты, модератор не пускает из лобби, BBB обновляет клиент.

## Этапы

1. Каркас бинарника, конфиг, systemd-пример, вайтлист id. Для ТГ — только `TELEGRAM_BOT_TOKEN`.
2. Парсер rasp + рефреш 4 раза в день + модель пар.
3. Telegram: онбординг только вайтлиста, T-15 Да/Нет, молчание = join.
3a. Mini App: вкладки Сейчас / Люди / Пары / Парсер / Логи, пуллинг 5–10 с, туннель HTTPS.
4. Память BBB-ссылок (спросить → сохранить → подставлять).
5. Join гостем, listen-only, лобби-алерт, рандомный выход 0–5 мин до конца.
6. SOCKS5 на вкладку, админская привязка кенту.
7. Один захват звука: файл на диск + лёгкие вейкворды в ТГ.
8. После пары: тот же файл на API расшифровки.

Пока нет рабочего парсера и памяти ссылок, в BBB не лезем: без URL комнаты остальное бесполезно.
