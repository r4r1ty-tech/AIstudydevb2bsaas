# План: бот на онлайн-лекции SSAU

Личный инструмент на ~5 человек одной группы. Не публичный SaaS.

## Зачем

Не сидеть на онлайн-парах, но:

1. **Посещаемость** — в BBB в списке участников видно ФИО, как в журнале. Камеру не просят, микрофон не нужен.
2. **Пейджер** — если препод сказал фамилию, «тест», «контрольная», «мудл»: сразу личка в Telegram. Квизы в Moodle руками, бот только пингует.
3. **Архив** — часть пар не пишется универом. Раз уже внутри комнаты, один раз пишем звук на диск VDS.

За 15 минут до пары в личку: предмет, препод, время, кнопки Да / Нет. Молчание = зайти. Нет = сегодня пропуск.

## Что сознательно не делаем

- Логин в личный кабинет и Moodle — слишком дорого и хрупко.
- Резидентские прокси и антибот-обход. Обычный SOCKS5 с RU IP, по одному на человека, настраивает админ.
- Автопрохождение тестов, ответы в чат BBB, включение камеры/микрофона.
- Отдельная копия записи на каждого кента, если это одна и та же лекция.

## Решения с гриля

| Тема | Решение |
| --- | --- |
| Кто | Я + кенты, одна группа, потолок ~5 человек |
| Площадка | `bbb.ssau.ru` (Greenlight), заход **гостем**, поле имени как скажет человек боту |
| Расписание | Публичный `https://ssau.ru/rasp?groupId=…`. Слово `online` в поле места — это онлайн, **не ссылка** |
| Ссылка BBB | В расписании её нет. При **первом** заходе на такую пару бот спрашивает URL `bbb.ssau.ru/b/…` и запоминает |
| Подгруппа | В профиле есть. Сейчас все в **1**, чужие подгрупповые онлайны не берём |
| Telegram | Один бот. Пишет только тому chat id, кто зарегистрировался. Вейкворды личные + общие |
| Прокси | SOCKS5, разные IP кентам. Раскидывает админ на VDS, не каждый в боте |
| Аудио в BBB | Всегда «только слушать». Лобби >2 мин → алерт «не пустили» |
| Выход | Случайные 0–5 минут **до** конца слота из расписания (преподы сами часто режут раньше) |
| Запись | Папка на VDS. Одна лекция = один файл, даже если зашло пятеро |
| Вейкворды | Общие: тест, контрольная, мудл. Плюс фамилия из того ФИО, как человека записали в BBB |
| Рефреш расписания | Фон: **07:00, 15:00, 19:00, 22:00** (локальное время Самары). Изменилось — перезаписать |

Группа-якорь: `6301-090301D`, `groupId=531023229`.

## Как это живёт

```
Telegram ──► bot (Go) ──► sqlite/json на диске
                 │
                 ├─ cron расписания (4 раза в день)
                 ├─ таймеры пар (T-15, join, leave)
                 └─ worker BBB
                       ├─ Chromium × N (по кенту, свой SOCKS5, своё ФИО)
                       └─ 1 захват звука на уникальную комнату/слот
```

Один процесс, один бинарник. Chromium ставится на VDS рядом, не бандлится в бинарник.

## Стек

**Go**, не Python и не «ещё один скрипт». Нужен маленький статичный бинарник на VDS: systemd, `scp`, всё.

Почему не Rust: автоматизация BBB — это браузер (WebRTC, гостевая форма, «только слушать»). В Go это `rod`/`chromedp` за дни, в Rust — боль. Парсер HTML, Telegram, cron, SOCKS5 — для Go родное.

Намётки пакетов (не догма):

- Telegram: `gotgbot` или `telego`
- Расписание: `net/http` + `goquery`
- Браузер: `go-rod/rod` (удобнее живого BBB, чем сырой chromedp)
- Хранение: SQLite (`modernc.org/sqlite` или `crawshaw`) — пользователи, ссылки BBB, снимок расписания
- Звук: системный Pulse/PipeWire + ffmpeg с вкладки Chromium, либо запись из виртуального синка
- STT на вейкворды: `whisper.cpp` или Vosk **рядом** с бинарником, не облако. Режем только триггеры, не пишем полный конспект в v1

Конфиг: `.env` + файл прокси. В git не попадает.

## Данные

**Пользователь:** telegram id, строка ФИО для BBB, groupId, подгруппа, включён ли, какой SOCKS5 ему назначен (ссылка на запись админа).

**Группа:** url/id расписания, последний сырой снимок, последний распарсенный список пар.

**Пара:** день, слот (08:00–09:35 и т.д.), дисциплина, препод, место (`online` / аудитория), подгруппа, тип.

**Ссылка BBB:** ключ ≈ `groupId + дисциплина + препод` (комната Greenlight обычно живёт семестр). Значение — URL. Если ключ пустой в момент T-15 — спросить ссылку в личке, без неё не заходить.

**Запись:** `recordings/{date}_{time}_{discipline}.ogg` плюс мета (кто из пользователей «присутствовал»).

## Онбординг в Telegram

1. Кент пишет боту.
2. Бот коротко говорит, зачем он: заход гостем на онлайны группы, алерты, запись на сервер.
3. Просит ссылку расписания (`https://ssau.ru/rasp?groupId=…`). Пока группа общая — можно принять тот же `531023229`.
4. Парсит неделю, отвечает «нашёл N онлайн-пар на этой неделе» или орёт, если страница не встала.
5. «Как тебя записать в BBB?» — человек присылает строку как в журнале. Из неё же берём фамилию для вейкворда (первое слово).
6. Подгруппа, дефолт `1`.
7. Дальше бот пишет только ему: преподы, кнопки, вейкворды.

Админ (ты): прокси и VDS руками, не через онбординг.

## Парсер `ssau.ru/rasp`

Публичная страница. Онлайн = `.schedule__place` содержит `online`. Препод — ссылка `/rasp?staffId=`. Подгруппа — текст `Подгруппы: N`. Слоты из колонки времени.

Рефреш в 7 / 15 / 19 / 22. Если сетка изменилась — перезаписать пары, пересчитать таймеры. Очные пары игнор, кроме того что они не должны порождать join.

Сайт иногда отдаёт 403 без нормального UA/cookie — парсеру нужен браузерный UA и, если понадобится, cookie с первой загрузки `/rasp` (как у чужих ssau-парсеров).

## Заход в BBB

На каждую включённую онлайн-пару и каждого кента с подходящей подгруппой:

1. T-15: карточка в ТГ (предмет, препод, время, Да/Нет).
2. Если ссылки комнаты нет — в той же карточке/следом: «кинь ссылку на подключение». Запомнить. Если так и не кинули — не заходим, написать об этом.
3. Молчание к концу окна / Да → поднять Chromium через SOCKS5 этого кента.
4. Открыть URL, вбить ФИО, join, выбрать **только слушать**.
5. Если зависли в waiting room — алерт.
6. Выйти в случайный момент из интервала `[конец_слота - 5 мин, конец_слота]`.

Пять человек на одной лекции = пять вкладок (пять имён в списке). Звук и STT — **один** пайплайн на этот слот+комнату.

## Вейкворды

Общие: `тест`, `контрольная`, `мудл` (и `moodle` как тот же смысл) → всем, кто сейчас «на этой паре».

Личные: фамилия из ФИО → только этому chat id.

Стрим STT с той единственной записи. Ложные срабатывания лучше резать коротким списком, чем копить «умные» синонимы.

## VDS

- Linux, Chromium, ffmpeg, бинарник под systemd.
- RAM: несколько живых WebRTC-вкладок, ориентир 8+ ГБ если пятеро одновременно.
- Диск под `recordings/`. Ротация не в v1, следить руками.
- Исходящие: Telegram API, `ssau.ru`, `bbb.ssau.ru`, SOCKS5.

## Риски (не прикидываемся, что их нет)

Посещаемость гостем с чужим/своим ФИО и запись пары — серая зона правил универа и BBB. Инструмент заточен под конкретную группу, репозиторий **приватный**. Не светить токены, прокси и записи.

Технически хрупко: смена вёрстки rasp, новая ссылка комнаты, модератор не пускает из лобби, BBB обновляет клиент.

## Этапы

1. Каркас бинарника, конфиг, systemd-пример.
2. Парсер rasp + рефреш 4 раза в день + модель пар.
3. Telegram: онбординг, T-15 Да/Нет, молчание = join.
4. Память BBB-ссылок (спросить → сохранить → подставлять).
5. Join гостем, listen-only, лобби-алерт, рандомный выход 0–5 мин до конца.
6. SOCKS5 на вкладку, админская привязка кенту.
7. Один захват звука на лекцию → папка на VDS.
8. STT только вейкворды → лички.

Пока нет рабочего парсера и памяти ссылок, в BBB не лезем: без URL комнаты остальное бесполезно.
