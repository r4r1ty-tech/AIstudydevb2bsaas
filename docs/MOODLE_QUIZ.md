# Moodle: устройство тестов (`mod/quiz`) и заметки для автоматизации

Документ составлен по разбору живых тестов курса «Теория информации» (`do.ssau.ru/moodle`, Moodle 4.5):
- `cmid=61422` («Неравномерное кодирование», `multichoice` с несколькими ответами, `deferredfeedback`, просмотр после завершения запрещён);
- `cmid=58084` («Декодирование неравномерных кодов и кодов Шеннона-Фано», `shortanswer`, `deferredfeedback`);
- `cmid=54867` («Коды Элиаса», `shortanswer`, `adaptive` с кнопкой «Проверить»);
- `cmid=45492` (`review.php` завершённой попытки, `multichoice` с одним ответом).

Клиент входа, `sesskey`, `websess` и парсинг списка элементов уже находятся в [`internal/moodle`](../internal/moodle/client.go).

## 1. Жизненный цикл попытки (`mod/quiz/*`)

1. **Страница теста** — `GET /moodle/mod/quiz/view.php?id=<cmid>`
   - Содержит правила (разрешено попыток, лимит времени, метод оценивания), список прошлых попыток (`table.quizreviewsummary`), блок `#feedback` и кнопку старта (или продолжения незавершённой попытки).
   - Если у теста есть ограничение по времени, в DOM сразу лежит форма диалога `#mod_quiz_preflight_form`.

2. **Старт попытки** — `POST /moodle/mod/quiz/startattempt.php`
   - Поля (`application/x-www-form-urlencoded`):
     - `cmid` — id элемента курса;
     - `sesskey` — CSRF-токен сессии со страницы;
     - `_qf__mod_quiz_form_preflight_check_form=1` и `submitbutton=Начать попытку` (для теста с preflight-модалкой).
   - Ответ: `303 See Other` → `Location: /moodle/mod/quiz/attempt.php?attempt=<attempt_id>&cmid=<cmid>`.

3. **Страница попытки** — `GET /moodle/mod/quiz/attempt.php?attempt=<attempt_id>&cmid=<cmid>`
   - Навигация и список слотов: ссылки `.qnbutton` в `#mod_quiz_navblock` и `.endtestlink` (`summary.php`).
   - Таймер: `#quiz-timer` / `#quiz-time-left`.
   - Главная форма ответов `#responseform` отправляется на `POST /moodle/mod/quiz/processattempt.php?cmid=<cmid>` (из браузера уходит как `multipart/form-data`).

4. **Сохранение / переход / проверка слота** — `POST /moodle/mod/quiz/processattempt.php?cmid=<cmid>`
   - Глобальные скрытые поля формы `#responseform`:
     - `attempt` — id попытки;
     - `thispage` — индекс текущей страницы (на одностраничном тесте `0`);
     - `nextpage` — индекс следующей страницы, либо `-1` на последней странице (переход к `summary.php`);
     - `timeup=0`;
     - `sesskey`;
     - `mdlscrollto` (можно `""` или `"0"`);
     - `slots` — номера слотов на текущей странице через запятую (`"1"`, `"1,2"`, `"1,2,3"`).
   - Поля на каждый слот `slot` (контейнер `.que`, `id="question-<qubaid>-<slot>"`):
     - `q<qubaid>:<slot>_:flagged` (`"0"` или `"1"`);
     - `q<qubaid>:<slot>_:sequencecheck` — счётчик состояния вопроса на сервере.
   - Управляющие поля (в зависимости от действия):
     - переход к следующей странице / в сводку: `next="Закончить попытку..."` (или текст кнопки перехода);
     - проверка конкретного вопроса в режиме `adaptive`: `q<qubaid>:<slot>_-submit=1` (без `next`).
   - Ответ: `303 See Other` → `summary.php?...` (при переходе на сводку) или обратно на `attempt.php?...&mdlscrollto=0` (после `_-submit`).

5. **Сводка попытки** — `GET /moodle/mod/quiz/summary.php?attempt=<attempt_id>&cmid=<cmid>`
   - Таблица состояний по слотам:
     - в `deferredfeedback` после сохранения: `"Ответ сохранен"`;
     - в `adaptive` до нажатия «Проверить»: `"Не завершено"` (даже если текст уже сохранён сервером), после проверки: `"Верно"` / `"Неверно"` и т.п.
   - Две формы:
     - возврат к попытке: `POST /moodle/mod/quiz/attempt.php` (`attempt`, `cmid`, `sesskey`);
     - окончательное завершение: `POST /moodle/mod/quiz/processattempt.php`.

6. **Завершение попытки** — `POST /moodle/mod/quiz/processattempt.php`
   - Поля (`application/x-www-form-urlencoded`):
     `attempt=<id>&finishattempt=1&timeup=0&slots=&cmid=<cmid>&sesskey=<sesskey>`.
   - Ответ: `303 See Other` → `review.php?attempt=<id>&cmid=<cmid>`.

7. **Обзор результата** — `GET /moodle/mod/quiz/review.php?attempt=<id>&cmid=<cmid>`
   - Если просмотр ответов открыт (`cmid=58084`, `54867`, `45492`), видны баллы, статус каждого вопроса и отзыв.
   - Если просмотр запрещён настройками теста (`cmid=61422`), `review.php` отдаёт `303` → `view.php?id=<cmid>` с алертом *«Вам не разрешен просмотр этого теста.»*. Итоговая оценка всё равно видна на `view.php` в `#feedback` и `table.quizreviewsummary`.

> [!IMPORTANT]
> Поле `q<qubaid>:<slot>_:sequencecheck` инкрементируется на сервере при возврате с `summary.php` и после каждого `_-submit` (например `1` → `2` → `3`). Перед каждым `POST processattempt.php` необходимо заново парсить `sequencecheck` и `sesskey` из актуального HTML страницы.

## 2. Типы и режимы вопросов (DOM)

Общий контейнер вопроса — `.que` с классами вида `que <qtype> <behaviour> <state>`:
- текст задания: `.qtext`;
- подсказка выбора: `.prompt`;
- блок ввода: `.answer`.

### `multichoice` — один вариант (`radio`, замечено в `cmid=45492`)
```html
<input type="radio" name="q570932:1_answer" value="0">
<input type="radio" name="q570932:1_answer" value="1">
```
Отправляется `q<qubaid>:<slot>_answer=<index>`.

### `multichoice` — несколько вариантов (`checkbox`, замечено в `cmid=61422`)
Внутри `.answer` для каждого варианта `.r0` / `.r1` идут **два** поля с одним `name`:
```html
<input type="hidden" name="q607183:1_choice0" value="0">
<input type="checkbox" name="q607183:1_choice0" value="1">
```
Текст варианта лежит в `[data-region="answer-label"]`. Отмеченный вариант отправляет пару `choiceN=0` и `choiceN=1` (в `multipart/form-data` побеждает `1`), неотмеченный — только `choiceN=0`.

### `shortanswer` — текстовый ввод (замечено в `cmid=58084`, `54867`)
```html
<input type="text" name="q607206:1_answer" id="q607206:1_answer" size="80">
```
Отправляется `q<qubaid>:<slot>_answer=<text>`.

### Поведение `adaptive` (кнопка «Проверить», замечено в `cmid=54867`)
Классы `.que.shortanswer.adaptive`. Внутри вопроса присутствует:
```html
<button type="submit" name="q607209:1_-submit" value="1">Проверить ...</button>
```
При отправке `q<qubaid>:<slot>_-submit=1` на `processattempt.php?cmid=<cmid>` в форме передаются ответы **всех** слотов текущей страницы (они сохраняются), а указанный слот сразу проверяется и получает статус на перезагруженной `attempt.php`.

## 3. Разбор решённых тестов и нетривиальные особенности

### Тест `cmid=61422` — Неравномерное кодирование
- 1 вопрос (`multichoice`, 5 чекбоксов): *«Выберите из списка ВСЕ коды, которые НЕ МОГУТ БЫТЬ использованы при неравномерном кодировании:»* (`11000100`, `0101100`, `110000`, `101000000`, `110111`).
- Подводный камень: по правилам неравномерного кодирования с разделителем `00` из курса (разделитель `00` включён в конец каждого кода, слово должно начинаться с `1`, заканчиваться на ровно один `00` и не содержать `00` внутри) все 5 вариантов оказались недопустимыми (`11000100`, `110000`, `101000000` содержат `00` внутри, `0101100` начинается с `0`, `110111` не оканчивается на `00`).

### Тест `cmid=58084` — Декодирование неравномерных кодов и Шеннона-Фано
- 2 вопроса (`shortanswer`): раскодировать битовые последовательности.
- **Подводный камень №1 (контекст в ресурсах курса):** таблиц кодов нет ни в тексте вопроса, ни на странице теста — они находятся в прикреплённой PDF-методичке курса (`mod_resource` → `pluginfile.php`, «Практикум по ТИ_исправленный.pdf», Таблица 1 и Таблица 2).
- **Подводный камень №2 (PDF-кодировка):** в PDF используются шрифты с разными `ToUnicode` CMap на каждый `/F<n>`. При извлечении текста нужно учитывать смену шрифта (`Tf`) по ходу потока, иначе кириллица превращается в мусор или теряется.
- **Подводный камень №3 (разрыв строки в HTML):** в задании по Шеннону-Фано длинная битовая последовательность была разбита на два `<p>...</p>` посередине кодового слова (`...010` и `10111...` → `0101` = `а`). При парсинге `.qtext` соседние абзацы битовых строк необходимо склеивать без пробела.
- **Подводный камень №4 (неоднозначность префиксов):** в неравномерном коде Таблицы 1 коды отличаются числом завершающих нулей (`о = 100`, `е = 1000`, `и = 10000`, пробел = `000`), поэтому разбор требует поиска допустимого разбиения по словарю (DFS/бэктрекинг), а не жадного префиксного матча.

### Тест `cmid=54867` — Коды Элиаса
- 3 вопроса (`shortanswer`, режим `adaptive`): построить гамма-, дельта- и омега-код Элиаса для заданных чисел без пробелов и разделителей.
- Алгоритмическая задача с точным побитовым ответом: обычная LLM при счёте длин и префиксов в уме часто ошибается на 1 бит, но при наличии вычислительного инструмента (или проверки кода скриптом) решается со 100% точностью.

### Что ещё не встречалось (нужно досмотреть на других тестах)
- Многостраничные тесты (`nextpage >= 0`, `attempt.php?attempt=...&page=N`, переходы назад/к конкретному `.qnbutton`).
- Вопросы на соответствие (`que match` — `<select>`).
- Числовые / вычисляемые (`que numerical`, `que calculated`).
- Drag-and-drop в текст/на картинку (`que ddwtos`, `que ddimageortext`) и вложенные ответы (`que multianswer` / Cloze).

## 4. Как подключать это к ИИ: API/Tool-ы vs MCP

Для LLM **нельзя** отдавать сырой HTML с `sequencecheck`, `sesskey` и `multipart/form-data` напрямую: модель должна видеть только чистую постановку задачи и вызывать высокоуровневые инструменты (tools), а всю работу с HTTP-сессией, куками, парсингом `.que` и валидацией формы делает детерминированный код (в Go — поверх `internal/moodle`).

### Рекомендуемый набор инструментов (контракт для LLM)

1. `list_course_materials(course_id)` / `read_material(cmid_or_url, query)` — доступ не только к конспектам лекций (`notes`, `transcript.txt`, слайды), но и к файлам/методичкам курса (`mod_resource`), с кэшированием извлечённого текста.
2. `get_quiz_info(cmid)` — состояние попыток, лимит времени, метод оценивания, разрешено ли уже начинать.
3. `start_or_resume_attempt(cmid)` — старт/продолжение попытки; возвращает структуру текущей страницы: `attempt_id`, таймер, `page`, `nextpage`, список вопросов (номер слота, тип `multichoice`/`shortanswer`/..., режим `adaptive`/`deferredfeedback`, текст, варианты ответа).
4. `submit_answers(attempt_id, answers, check_slot?)` — подставляет ответы в форму с актуальными `sequencecheck`/`sesskey`, при `adaptive` может нажать `_-submit` для конкретного слота и вернуть его мгновенный вердикт (`Верно`/`Неверно`) и обновлённые данные страницы.
5. `finish_attempt(attempt_id)` — переход в `summary.php` и отправка `finishattempt=1` (либо только подготовка к подтверждению пользователем перед финальной отправкой).
6. `eval_script` / `python` (песочница) — для расчётов, кодирования/декодирования, формул и перебора вариантов, чтобы LLM не считала биты и числа «в уме».

### Что выбрать: встроенное API в Go (OpenAI tool calling) или MCP?

- **Основной путь для прод-бота и панели (из [`PLAN.md`](../PLAN.md)) — встроенный agent loop в Go через Tool Calling (API), без отдельного MCP-сервера.**
  - В проекте уже есть шифрованные куки Moodle в `accounts` (`internal/vault`), `internal/moodle`, `internal/notes/llm.go` (OpenAI-compatible `chat/completions`), веб-панель и Telegram-бот.
  - В режиме API-агента процесс сам держит состояние попытки в памяти, при необходимости ставит паузу перед `finish_attempt` и присылает в Telegram/Mini App карточку «Вот выбранные ответы — подтвердить отправку?».
  - На VDS (4 CPU / 4 GB RAM) это не требует лишних процессов и браузера (всё работает на чистом HTTP в Go).
- **MCP-сервер — как опциональная обёртка поверх того же Go-пакета**, если захочется запускать прохождение тестов вручную из IDE/агента (Claude/Cursor/Antigravity) под своим локальным контролем. Движок квизов реализован в [`internal/moodle/quiz.go`](../internal/moodle/quiz.go), а встроенный решатель и реакция на открытие тестов — в [`internal/uni/quiz_solve.go`](../internal/uni/quiz_solve.go), [`internal/uni/quiz_agent.go`](../internal/uni/quiz_agent.go) и [`internal/uni/run.go`](../internal/uni/run.go).

## 5. Параллельное и защищённое решение тестов (реализовано)

1. **Очередь и воркеры (`internal/uni/run.go`):**
   - Число параллельных воркеров задаётся переменной `MOODLE_WORKERS` (`MoodleWorkersLimit()`, по умолчанию `4`).
   - `sortMoodleTasks` ставит задачи с `kicked` / `wakeKicked` (кнопка «Пройти» или вейкворд на паре) перед плановыми обходами.
   - `TryLockQuiz` / `UnlockQuiz` (ключ `<tgID>:<quizID>`) гарантирует, что один и тот же тест не решается одновременно двумя тиками или воркерами.

2. **Бюджет времени и быстрый режим (`internal/uni/quiz_solve.go`, `quiz_agent.go`):**
   - `parseTimeLeft` читает таймер Moodle со страницы попытки; от конца отступается резерв `quizTimeReserve = 75s`.
   - `pageOptsForWave` включает `FastMode`, если до окончания времени осталось меньше `quizFastModeTimeLeft = 3m` или расчёт волн показывает нехватку времени (`wavesLeft * quizWaveBudget`, где `quizWaveBudget = 45s`), либо во время решения до дедлайна остаётся меньше `quizFastModeRemaining = 60s`. В `FastMode` отключаются веб-поиск и дополнительные раунды уточнений (в обычном режиме их до `quizMaxRounds = 3`).

3. **Параллельные страницы и последовательная отправка (`internal/uni/quiz_solve.go`):**
   - Для тестов со свободной навигацией `solveAndSubmitFreeNav` решает до `quizPageWorkers = 4` страниц за волну параллельно, но вызывает `submitPageAnswers` строго последовательно по возрастанию индекса страницы, как только готовы очередные смежные страницы.
   - При обнаружении `sequential`-навигации (`next.Page != cur.NextPage` или повтор страницы) решатель автоматически переключается на `solveAndSubmitSeqNav` (строго страница за страницей).

4. **Параллельное распознавание картинок (`internal/uni/quiz_agent.go`):**
   - `describeQuestionImages` обрабатывает до `quizMaxImages = 4` изображений на вопрос пулом из `quizImageWorkers = 4` воркеров через `notes.DescribeImage` и раскладывает описания обратно в детерминированном порядке вопросов и слотов.

5. **Ключи ИИ и материалы курса:**
   - Цепочка строится через `access.QuizChainWithVault(st, vault, cfg, tgID)` — не-админ изолирован только своими ключами (личные из `llm_keys` и подписанные фамилией из `.env`), админ имеет свой выбор -> `cheaper` -> пул.
   - `collectCourseMaterials` подтягивает свежие `notes.md` и `transcript.txt` из `ListPacks` по совпадающей дисциплине (до `32 000` символов).

6. **Защита от SSRF при чтении страниц из поиска (`internal/uni/quiz_agent.go`):**
   - `openPage` проверяет URL через `validatePageURL` (разрешены только `http:` и `https:`, запрещены `localhost`, `.localhost`, `.local`, `.internal`, `.arpa` и приватные/loopback/link-local/multicast/CGNAT `100.64.0.0/10` адреса).
   - `safeDialContext` и `CheckRedirect` (до `quizMaxRedirects = 5`) повторно резолвят и проверяют IP перед соединением и на каждом редиректе, блокируя DNS rebinding и доступ во внутреннюю сеть VDS.

## 6. База проверенных ответов (реализовано)

Идея: Moodle сам подтверждает, какие ответы верны. Верные ответы пишутся в базу, и при следующем решении того же вопроса (другой студент, повтор) ответ берётся из базы без ИИ.

1. **Что попадает в базу (`internal/moodle/review.go`, `internal/uni/quiz_answers.go`):**
   - После успешного `FinishAttempt` в `processQuizErr` вызывается `recordVerifiedAnswers` (одна строка в `quiz_solve.go`). Функция запрашивает `review.php?attempt=…&showall=1` и разбирает каждый вопрос.
   - Отметка правильности: класс `.que` (`correct` / `incorrect` / `partiallycorrect`), блок состояния («Верно», «Неверно», «Частично правильно»), фраза «Ваш ответ верный/неверный». Баллы «Баллов: 1,00 из 1,00» служат проверкой: при расхождении отметки с баллами отметка не используется.
   - Если отметки по вопросам скрыты настройками теста, а итог попытки равен максимуму (`«10,00 из 10,00»`), все ответы считаются правильными (`ByTotal`).
   - Во всех остальных случаях (частично, неверно, отметки скрыты и итог неполный, просмотр закрыт) в базу ничего не пишется.
   - Ошибка записи только логируется и не влияет на решение теста.

2. **Как устроен ключ (`quizQuestionHash`):**
   - `qhash` = sha256 от нормализованного условия, типа вопроса и отсортированного набора вариантов (`v:` — варианты выбора, `q:` — подвопросы соответствия).
   - Нормализация: без HTML, нижний регистр, `ё` → `е`, пробелы схлопнуты. Одна функция используется и для записи, и для поиска.
   - Ответ хранится в `answer_json` по **тексту** вариантов (`choice`, `choices`, `text`, `matches`), а не по индексам: Moodle перемешивает варианты. При поиске тексты сопоставляются с текущими вариантами страницы.

3. **Таблица `quiz_answers` (`internal/store/quiz_answers.go`):**
   - Поля: `course`, `cmid`, `qhash` (уникальный), `qtype`, `question_text`, `answer_json`, `verified_at`, `source_tg`, `hits`, `created_at`.
   - Поиск глобальный по `qhash`: один банк вопросов в разных курсах даёт одну запись. `course` и `cmid` только для справки.
   - Повторная запись на тот же `qhash` заменяет ответ последним подтверждённым и сохраняет счётчик `hits`. `LookupAnswer` увеличивает `hits` при каждом попадании.

4. **Решение страницы (`solvePageWithOpts` в `quiz_agent.go`):**
   - Сначала каждый вопрос страницы ищется в базе, найденный ответ сопоставляется с вариантами и проверяется `validateAnswers`. Иначе вопрос считается ненайденным.
   - ИИ вызывается только для ненайденных вопросов (`solvePageAI`). Если на странице всё найдено, ИИ не вызывается вовсе.
   - Ответы из базы отмечаются в отчёте страницы (`quizlog.Page.Notes`: «ответы из базы проверенных: слоты […]»). В журнале пишется «из базы проверенных ответов N из M вопросов, через ИИ K».

5. **Отрицательная память (`quiz_wrong_answers`):** ответы из review с отметкой «Неверно» пишутся в `quiz_wrong_answers` (по `qhash` и тексту ответа). При следующем решении они передаются модели в промпте («УЖЕ ПРОВЕРЕНО: неверно»). Если модель всё же выбрала известный неверный ответ, делается один повтор запроса только для этих вопросов; повтор, давший тот же ответ, отправляется как есть и пишется в журнал.

6. **Оценка неполная (`processQuizErr`, `retryDecision`):**
   - «Решён» и отметка `solvedKey` ставятся только при полной оценке «X из Y» (или если оценку не удалось разобрать — как раньше).
   - При X < Y читается `view.php`: «Разрешено попыток», «Метод оценивания», число завершённых попыток (`moodle.QuizInfo`). Автоповтор новой попыткой (`retryDecision`) — только если:
     - в базе появилось новое знание (`recordVerifiedAnswers` вернул новые верные или неверные записи; закрытый просмотр — знания нет);
     - попытки остались;
     - ненулевая оценка: метод «Высшая оценка»; ноль баллов: «Высшая оценка» или «Последняя попытка» (не «Первая» и не «Средняя»);
     - при неограниченном числе попыток не больше `quizUnlimitedRetries = 3` автоповторов подряд.
   - Каждый автоповтор увеличивает `quiz_fail` и ограничен `quizMaxAttempts = 6`.
   - При методе «Последняя попытка» и X > 0 повтора нет: тест не помечается решённым, `quiz_fail` сбрасывается, синк его сам не запускает, в отчёте — «нажми „Пройти“, осталось попыток N».

7. **Без ключа ИИ (`processQuizErr`):** цепочка ИИ вычисляется до старта попытки.
   - Новую попытку без ключа не начинаем. Если студент открыл попытку сам (`InProgressAttemptID`), читаем вопросы из неё: все найдены в базе — решаем из базы и завершаем; иначе присылаем текст, попытку не трогаем.
   - Без открытой попытки — одно сообщение «нужен ключ ИИ в панели или пройди тест сам» (по тесту один раз, без «Пройти»).
   - «Пройти» и в базе есть записи по этому cmid (`CountVerifiedForCMID`) — попытку начинаем. Если покрыто не всё, присылаем текст и предупреждаем, что попытка открыта.

8. **Отчёт в Telegram (`buildQuizReport`):** заголовок «✅ Тест решён: X из Y» при полной оценке, иначе «Тест Moodle: оценка X из Y» с подсказкой, что делать дальше. Строки: курс, тест, модель и уверенность, материалы курса (есть/нет), веб-поиск (работал/капча/нет), «из базы N, через ИИ K». По каждому вопросу — условие (до 120 символов) и ответ в `<pre>`. Длина ограничена 3500 символами, остальные вопросы заменяются строкой «… и ещё N вопросов». Все подстановки экранируются.

9. **Формат и пример из условия (`formatSection`, `quizQuery`):** раздел «Формат ответа» / «Пример» попадает в промпт отдельным блоком с требованием строго следовать формату. В поиск (`quizQuery`) этот раздел не идёт: поиск получает только суть задачи.

10. **Ограничения:**
   - Если просмотр попытки закрыт настройками, записывать нечего: вопросы и ответы без review не читаются.
   - Оценка «X из Y» читается из строки «Оценка» на странице review; если Moodle её не показывает, тест считается решённым (как раньше).
   - Таблица `quiz_answers` хранит верные ответы, `quiz_wrong_answers` — неверные. Ответ, который Moodle позже отметил неверным, удаляется из `quiz_answers` (отравленная база), а верный — из `quiz_wrong_answers`. При поиске запись, совпадающая с известным неверным, считается ненайденной.
   - Вопросы с рисунком не пишутся в базу и не ищутся по ней. Варианты с одинаковым текстом делают ответ неоднозначным: такой ответ не пишется и не сопоставляется.
   - Правильный ответ из блока «Правильный ответ» неверного вопроса пишется как верный, если однозначно сопоставляется с вариантом (один вариант выбора или короткий ответ). Соответствия и множественный выбор этим путём не разбираются.
